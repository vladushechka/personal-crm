# Personal CRM

Контакты людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, заметки о разговорах.

## Как запустить

### Что нужно

- Docker Desktop - должен быть запущен
- Node.js 24 и pnpm

### База данных

1. Если файла `.env` ещё нет - скопируйте `.env.example` в `.env` и заполните значения
2. Запустите базу:

   ```
   docker compose up -d
   ```

3. Проверьте, что она работает:

   ```
   docker compose ps
   ```

   В колонке STATUS должно быть `healthy`

Остановить базу: `docker compose stop`. Данные при этом сохраняются.

### Приложение

Первый запуск (один раз):

```
pnpm install
pnpm db:migrate
pnpm db:seed
```

- `pnpm db:migrate` - создаёт таблицы в базе. Повторять после обновления кода: команда применит только новые изменения
- `pnpm db:seed` - добавляет 1000 тестовых контактов. Срабатывает, только если база пустая: настоящие контакты не смешаются с тестовыми

Запуск:

```
pnpm build
pnpm start
```

Откройте в браузере http://localhost:3000

Остановить: нажмите `Ctrl+C` в окне, где запущен `pnpm start`, или просто закройте это окно.

Приложение открывается только на этом компьютере: с других устройств в сети оно недоступно, потому что входа по паролю нет.

## Как проверить, что всё работает

Руками:

1. Откройте http://localhost:3000 - видно список всех контактов и их число
2. «Добавить контакт» → заполните имя → «Сохранить контакт» - контакт подсвечен в списке
3. Наберите часть имени в поиске → откройте карточку → допишите заметку → «Сохранить заметку»
4. Обновите страницу - заметка на месте
5. Откройте тот же адрес в другом браузере - те же контакты и заметки
6. В карточке контакта «Изменить» → поменяйте поля → «Сохранить изменения» - в карточке новые данные и сообщение «Изменения сохранены»
7. У заметки карандаш → поменяйте текст → «Сохранить» или Ctrl+Enter - текст новый, дата та же. «Отмена» или Esc - ничего не меняется
8. У заметки корзина → «Удалить» - заметки нет, остальные на месте. «Отмена» в окне - заметка остаётся

Автоматически: `pnpm test:e2e`. Тест проходит те же шаги в Google Chrome и Microsoft Edge.
Он работает с отдельной базой `personal_crm_e2e` и пересоздаёт её при каждом запуске - ваши контакты не затрагиваются.

## Выкатка

Адрес: https://app.vladmath.com

Изменения попадают в `main` только через PR, и каждое вливание в `main` - это выкатка. Сама она идёт так (вкладка Actions на GitHub):

1. GitHub собирает образ приложения (`Dockerfile`) и кладёт его в GHCR с меткой - хешем коммита
2. Копирует `deploy/` на сервер в `/opt/crm/prod` и запускает `deploy.sh`
3. На сервере: миграции базы → новая версия приложения → проверка `/health`

Если миграции упали - новая версия не запускается, работает старая. Если `/health` не отвечает 200 - выкатка красная, ничего само не откатывается.

### Как проверить

- Откройте https://app.vladmath.com
- https://app.vladmath.com/health - должно быть `{"status":"ok"}`

### На сервере

Зайти: `ssh crm`. Всё приложение - в `/opt/crm/prod`:

- `.env` - пароль базы, права 600. Пишется руками, в git не попадает
- `current-image`, `previous-image` - текущая и предыдущая версии

Посмотреть, что запущено, и логи:

```
cd /opt/crm/prod
APP_IMAGE=$(cat current-image) docker compose -p prod ps
APP_IMAGE=$(cat current-image) docker compose -p prod logs app --tail 50
```

Откат на предыдущую версию (вручную):

```
bash /opt/crm/prod/deploy.sh "$(cat /opt/crm/prod/previous-image)"
```

## Для разработки

- `pnpm dev` - режим разработки, страницы обновляются при изменении кода
- `pnpm typecheck`, `pnpm lint` - проверка кода
- После изменения схемы в `src/db/schema.ts`: `pnpm db:generate`, затем `pnpm db:migrate`
