# Personal CRM

Контакты людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, заметки о разговорах.

## Как запустить

### Что нужно

- Docker Desktop - должен быть запущен
- Node.js 24 и pnpm

### База данных и почтовый ящик

1. Если файла `.env` ещё нет - скопируйте `.env.example` в `.env` и заполните значения. Что куда писать, сказано в комментариях `.env.example`. В `OWNER_EMAIL` - ваша почта: ей достаются контакты, которые уже есть в базе, и тестовые данные
2. Запустите базу и почтовый ящик-заглушку Mailpit:

   ```
   docker compose up -d
   ```

3. Проверьте, что она работает:

   ```
   docker compose ps
   ```

   В колонке STATUS у `db` и `mailpit` должно быть `healthy`

Остановить: `docker compose stop`. Данные при этом сохраняются.

Mailpit ловит все письма, которые отправляет приложение на этом компьютере: никуда наружу они не уходят. Ящик открывается в браузере: http://localhost:8025

### Приложение

Первый запуск (один раз):

```
pnpm install
pnpm db:migrate
pnpm db:seed
```

- `pnpm db:migrate` - создаёт таблицы в базе. Повторять после обновления кода: команда применит только новые изменения. Если в базе уже есть контакты, а `OWNER_EMAIL` не задан, миграция входа остановится и ничего не изменит
- `pnpm db:seed` - добавляет 1000 тестовых контактов, примерно каждому десятому - частоту общения для блока «Пора связаться», примерно каждому третьему - группы. Срабатывает, только если база пустая: настоящие контакты не смешаются с тестовыми
- `pnpm db:seed:keep-in-touch` - один раз для базы, заполненной до появления «Пора связаться»: даёт примерно каждому десятому контакту случайную частоту общения. Ничего не делает, если частота уже есть хоть у одного контакта
- `pnpm db:seed:groups` - один раз для базы, заполненной до появления групп: создаёт тестовые группы и раскладывает по ним примерно треть контактов. Ничего не делает, если хоть одна группа уже есть

Запуск:

```
pnpm build
pnpm start
```

Откройте в браузере http://localhost:3000

Остановить: нажмите `Ctrl+C` в окне, где запущен `pnpm start`, или просто закройте это окно.

Приложение открывается только на этом компьютере: с других устройств в сети оно недоступно.

### Вход на этом компьютере

1. На http://localhost:3000 введите почту и нажмите «Получить ссылку». Подойдёт любая почта: письмо никуда не уйдёт
2. Откройте ящик http://localhost:8025, письмо «Вход в Personal CRM», кнопка «Войти»
3. Своя почта из `OWNER_EMAIL` - видны все ваши контакты. Любая другая - пустой список: так проверяется второй пользователь

## Как проверить, что всё работает

Руками:

1. Откройте http://localhost:3000 - видно список всех контактов и их число
2. «Добавить контакт» → заполните имя → «Сохранить контакт» - контакт подсвечен в списке
3. Наберите часть имени в поиске → откройте карточку → допишите заметку → «Сохранить заметку»
4. Обновите страницу - заметка на месте
5. Откройте тот же адрес в другом браузере - те же контакты и заметки
6. В карточке контакта «Изменить» → поменяйте поля → «Сохранить изменения» - в карточке новые данные и сообщение «Изменения сохранены»
7. У заметки карандаш → поменяйте текст → «Сохранить» или Ctrl+Enter - текст новый, дата та же. «Отмена» или Esc - ничего не меняется
8. У заметки корзина → «Удалить» - заметки нет, остальные на месте. «Отмена» в окне - заметка остаётся
9. В карточке «Как часто общаться» → «Раз в месяц» → обновите страницу - выбрано «Раз в месяц»
10. Если последней заметке больше месяца - на главной контакт в блоке «Пора связаться», самые просроченные сверху. Допишите ему заметку - он пропал из блока
11. Наберите что-нибудь в поиске - блока нет. В блоке больше пяти человек - кнопка «Показать всех (N)» показывает остальных
12. В карточке контакта в поле «Новая группа» введите название и нажмите Enter - группа появилась и отмечена. Нажмите на неё ещё раз - отметка снята
13. На главной нажмите на группу - в списке только её люди, поиск работает внутри неё, «Все» возвращает полный список. Под именами в списке видны метки групп
14. На главной «Настроить» - страница «Группы»: карандаш переименовывает группу, корзина удаляет, контакты остаются
15. Без входа любая страница показывает страницу входа. Вход - по ссылке из письма, см. «Вход на этом компьютере». В шапке ваша почта и «Выйти»
16. Ссылка из письма работает один раз и 15 минут; вторая ссылка гасит первую - «Ссылка устарела, запроси новую». Больше 3 писем на одну почту за 10 минут - «Слишком часто, попробуй через несколько минут»
17. Войдите другой почтой в другом браузере или окне инкогнито: список пуст, «Добавь первый контакт». Добавьте контакт - в первом браузере его нет. Ссылка на чужой контакт - «Контакт не найден»

Автоматически:

- `pnpm test` - быстрые тесты правил, секунды, браузер и база не нужны
- `pnpm test:e2e` - тест проходит те же шаги в Google Chrome и Microsoft Edge. Нужны запущенные база и Mailpit: тесты берут ссылки входа из ящика

`pnpm test:e2e` работает с отдельной базой `personal_crm_e2e` и пересоздаёт её при каждом запуске - ваши контакты не затрагиваются.

### Автопроверка на GitHub

На каждый PR в `main` GitHub сам запускает проверку (`.github/workflows/ci.yml`, вкладка Checks в PR):

- `checks` - оформление кода (`pnpm lint`, `pnpm format:check`), типы, быстрые тесты
- `e2e` - браузерные тесты на собранном приложении, как на сервере
- `image` - образ приложения собирается

`main` защищена: PR вливается, только когда все три зелёные, и тогда вливается сам. Красный PR не влить даже руками.

## Выкатка

Адрес: https://app.vladmath.com

Изменения попадают в `main` только через PR, и каждое вливание в `main` - это выкатка. Сама она идёт так (вкладка Actions на GitHub):

1. GitHub собирает образ приложения (`Dockerfile`) и кладёт его в GHCR с меткой - хешем коммита
2. Копирует всю папку `deploy/` на сервер в `/opt/crm/prod` и запускает `deploy.sh`
3. На сервере: копия базы → миграции базы → новая версия приложения → проверка `/health`

Если копия базы не снялась или миграции упали - новая версия не запускается, работает старая. Если `/health` не отвечает 200 - выкатка красная, ничего само не откатывается.

### Как проверить

- Откройте https://app.vladmath.com
- https://app.vladmath.com/health - должно быть `{"status":"ok"}`

### На сервере

Зайти: `ssh crm`. Всё приложение - в `/opt/crm/prod`:

- `.env` - пароль базы, права 600. Пишется руками, в git не попадает
- `current-image`, `previous-image` - текущая и предыдущая версии
- `backups/` - копии базы, читает только владелец папки: внутри личные данные

Посмотреть, что запущено, и логи:

```
cd /opt/crm/prod
APP_IMAGE=$(cat current-image) docker compose -p prod ps
APP_IMAGE=$(cat current-image) docker compose -p prod logs app --tail 50
```

Один раз после выкатки «Пора связаться» - частоты общения тестовым контактам:

```
cd /opt/crm/prod
APP_IMAGE=$(cat current-image) docker compose -p prod run --rm migrate node_modules/.bin/tsx scripts/seed-keep-in-touch.ts
```

Один раз после выкатки групп - тестовые группы:

```
cd /opt/crm/prod
APP_IMAGE=$(cat current-image) docker compose -p prod run --rm migrate node_modules/.bin/tsx scripts/seed-groups.ts
```

Откат на предыдущую версию (вручную):

```
bash /opt/crm/prod/deploy.sh "$(cat /opt/crm/prod/previous-image)"
```

### Настройки на сервере

В `/opt/crm/prod/.env` (права 600, пишет владелец руками), кроме пароля базы:

- `BETTER_AUTH_SECRET` - секрет входа, 32+ случайных символа, свой для сервера
- `BETTER_AUTH_URL=https://app.vladmath.com`
- `SMTP_URL=smtps://resend:КЛЮЧ@smtp.resend.com:465` - ключ Resend только на отправку с домена `mail.app.vladmath.com`
- `MAIL_FROM="Personal CRM <noreply@mail.app.vladmath.com>"`
- `OWNER_EMAIL` - почта владельца: ей достаются контакты, которые были до входа, и тестовые данные

### Бэкапы и восстановление

Каждая выкатка перед миграциями сама снимает копию базы в `/opt/crm/prod/backups`. В имени - дата и время по Москве и версия, которая стояла до выкатки: `2026-11-08_023000_6a9ab34_before-deploy.dump`. Старые копии пока не удаляются.

Посмотреть копии:

```
ssh crm
ls -lh /opt/crm/prod/backups
```

Снять копию руками, например перед опасной операцией:

```
bash /opt/crm/prod/backup.sh manual
```

Восстановить базу из копии - запускаете только вы:

1. `ssh crm`
2. `cd /opt/crm/prod && ls -lh backups` - выберите файл
3. `bash restore.sh backups/<файл>.dump`
4. Скрипт покажет, какую базу и каким файлом заменит. Напечатайте `yes` и Enter. Любой другой ответ - выход, ничего не меняется
5. Дальше он сам: снимает копию текущей базы (`..._before-restore.dump`, по ней можно вернуться), останавливает приложение, удаляет базу, создаёт пустую, загружает копию, поднимает приложение той же версии и проверяет `/health`
6. В конце `Restored ...` - готово. Откройте https://app.vladmath.com

Полный откат после выкатки, которая поменяла базу (например, вход и пользователи): приложение и база откатываются только вместе.

1. Сначала прошлая версия приложения: `bash /opt/crm/prod/deploy.sh "$(cat /opt/crm/prod/previous-image)"`
2. Потом база из копии, снятой перед плохой выкаткой: `bash /opt/crm/prod/restore.sh backups/<дата>_<прошлая версия>_before-deploy.dump`. Прошлая версия - первые 7 символов из `previous-image`

## Для разработки

- `pnpm dev` - режим разработки, страницы обновляются при изменении кода
- `pnpm typecheck`, `pnpm lint` - проверка кода
- `pnpm format` - выровнять оформление кода (Prettier); `pnpm format:check` - только проверить, как в автопроверке
- После изменения схемы в `src/db/schema.ts`: `pnpm db:generate`, затем `pnpm db:migrate`
